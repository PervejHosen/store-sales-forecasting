Store Sales Forecasting

Store managers plan staff and stock six weeks ahead, so every forecast error turns into an empty shelf or a queue at the till. This project forecasts daily sales for drugstores six weeks ahead, tests four methods the way they would really be used, and shows where each one breaks.

Four ways to forecast, tested honestly

Each method forecasts 6 weeks at a time, using only data from before the window starts, in four separate windows that include Christmas and Easter. This is how the forecast would be used for real, and it is the step most portfolio forecasts skip.

Error in each test window

WAPE: total absolute error as a share of actual sales · lower is better

The scorecard

All four windows pooled · store-days

RMSPE is the root mean square percentage error used in the original Kaggle competition. Bias above zero means the forecast runs high. "Off 15%+" is the share of store-days where a roster built on the forecast would clearly be wrong. "Weekly" is the WAPE on each store's weekly totals.

    The four methods

    Each one is a step up in effort, and each has to earn its place against the one before

    MethodHow it forecastsUses promotions?
    Seasonal naiveSame weekday 52 weeks earlierNo
    Planner averageThe store's average for that weekday over the last 12 weeks, split by promotion week. What a planner would build in a spreadsheet.Yes
    ETSExponential smoothing with a weekly season, fitted per store on the last year (statsforecast AutoETS)No
    LightGBMOne model for all stores, trained on log sales with calendar, promotion, holiday, refurbishment, competitor and store-history features. Two extra quantile models give the 80% range.Yes

    No leakage: every feature for a forecast day is either known in advance (the promotion calendar, public and school holidays, planned closures, store facts) or measured at least 42 days earlier, so the same features exist on the day the forecast is made. Test windows are never used for training or tuning.
